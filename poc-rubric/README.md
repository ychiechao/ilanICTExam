# 積木作品檢核點 PoC

驗證「範例檔 → 檢核點 → 逐條比對學生作品」的可行性。獨立單頁，不動主程式。

## 執行

```bash
npm run dev
```

開 http://localhost:5173/poc-rubric/index.html （需要經由 http 載入，直接開檔案會抓不到內建範例）。

## 內容

- `index.html`：解析 `.aia`（`.scm` 元件樹 + `.bky` Blockly XML）與 `.sb3`（`project.json`），正規化後產生檢核點候選；上傳學生作品後逐條比對、計分，另附結構相似度（Jaccard，僅參考）。
- `make-samples.mjs`：產生 `samples/` 下的範例檔（`node poc-rubric/make-samples.mjs`）。
  - `ai2-*`：按鈕計算 1..N 總和。A 命名／版面不同但邏輯相同；B 改用 while；C 只把 Label 設成 Hello。
  - `sb3-*`：加總清單「輸入」到變數「答案」。A 角色改名並多一個角色；B 計數變數改名為「索引」、改用「說 2 秒」；C 只會說 Hello。

## 正規化規則（目前）

| 不計 | 計 |
| --- | --- |
| 元件名稱、Width/Height/顏色/字型、座標、積木 id | 元件型別與數量、事件處理器（型別.事件）、腳本內出現的積木種類、程序名稱與參數數 |
| App Inventor 全域變數名稱（只算數量） | Scratch 變數／清單名稱（因為 I/O 約定會靠名稱） |
| 常數值預設不勾，出題者可勾 | |

## 已知限制

- 同一邏輯不同寫法（for vs while）會在對應項目失分——這是設計上的取捨，題目要寫明「依範例規畫實作」，或由出題者把該項取消勾選。
- Scratch 變數以名稱比對，學生改名就會失分；若要名稱不敏感，需要另做「依型別＋出現順序」的對應。
- 只檢查「有沒有用到」，不檢查順序與巢狀關係（例如「加法必須在迴圈裡面」）。加上 `edges`（父子關係）就能做到，資料已經算好，只是還沒變成檢核點。
- 未處理多畫面 `.aia` 的畫面對應（目前把所有畫面的元件與腳本混在一起）。
